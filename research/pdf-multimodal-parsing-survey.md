# PDF 多要素解析技术方案调研

> 目标：一份同时包含**文字（版式/字体/多栏）、图片、表格、电路图、波形图、FSM 示意图**的 PDF，如何系统化地解析成可追溯的结构化数据。
> 视角：EDA / 芯片数据手册 / 学术论文 / 教材，工程可落地优先，不是模型综述。
> 版本：v1.0 ｜ 截止 2026-10

---

## 0. 结论先行

五条核心判断，后面所有章节都是它们的展开：

1. **PDF 不是一个东西，是两个世界。**
   原生数字 PDF：有字符级坐标、字体名/字号、矢量路径、可选的结构标签树（Tagged PDF）。能"解剖"就不要"看图"。
   扫描 PDF：只有像素，必须走视觉模型。
   **绝大多数架构错误，来自把这两类页面塞进同一条流水线。**

2. **通用文档解析已经"够用"，但只覆盖到表格为止。**
   MinerU 2.5 / PaddleOCR-VL-1.5 / GLM-OCR / Docling 把「文字+版面+阅读顺序+表格+公式」做到了工程可用；但遇到电路图、波形图、FSM 图，它们统一输出**图片占位符**，零语义。EDA 图形必须自建领域解析层。

3. **电路图 / 波形图 / FSM 的正确抽象不是"识别"，而是"图的重建"。**
   把三类图统一看成 **节点 + 边 + 标签 + 坐标/刻度**：
   | 图类型 | 节点 | 边 | 标签 | 附加结构 |
   |---|---|---|---|---|
   | 电路图 | 器件符号 | 导线（含 junction dot） | 位号、参数 | 网表拓扑 |
   | 波形图 | 关键点/边沿 | 线段、曲线 | 时间/电压刻度、箭头标注 | 时序关系、值序列 |
   | FSM | 状态框 | 有向迁移箭头 | 状态名、迁移条件 | 状态转移图、可达性 |
   一旦这样建模，三类图可以**共用同一套"检测 → 几何关联 → 图构建 → 校验"骨架**，只是后端输出不同（网表 / CSV / DOT）。

4. **VLM 擅长语义，不擅长精确性与完整性。**
   已公开的硬数据：GPT-4 在电路图上识别元件约 90%，但识别**连接关系**掉到约 45%（AMSNet）；Gemini 在一张 12 类分组柱状图上输出的表格 **36 格错 23 格**，且错在最不可能出错的零高度柱。
   正确用法：**几何/矢量给事实，VLM 给语义，规则+仿真给校验**。

5. **端到端大模型直接吞混合 PDF，目前是幻觉流水线。**
   工程解是「**分诊 + 三通道 + 校验门**」：Native 通道（确定性）→ 视觉通道（概率性）→ 语义通道（生成性），每一级只允许做它不会撒谎的事。

### 选型速查

| 需求 | 首选 | 备选 | 理由 |
|---|---|---|---|
| 通用文档 → Markdown 供 RAG | PaddleOCR-VL-1.5（0.9B，Apache-2.0） | GLM-OCR / MinerU 2.5 | 综合分与吞吐均领先，多边形框支持倾斜/褶皱扫描件 |
| 中文密集 + 复杂表格 | GLM-OCR（Table-TEDS 最高） | PaddleOCR-VL-1.5 | 表格是分水岭指标 |
| 纯 CPU / 离线 / 强合规 | Docling + PyMuPDF | pymupdf4llm | 一条 `pip install` 搞定，MIT |
| 极致吞吐 / 自建数据工厂 | DeepSeek-OCR 2（MIT，单 A100 约 20 万页/天†） | PaddleOCR-VL + vLLM | 光学压缩把 token 降到 1/6 |
| EDA datasheet 全要素 | **自建：Native 优先 + 领域解析层** | 商用 API 兜底 | 现成工具对图无语义 |
| 电路图 → 网表 | 检测式（YOLO + 线分割 + 图重建）+ 仿真校验 | VLM 直出 SPICE + ngspice 过滤 | 纯 VLM 连接准确率不足 |
| 波形图取值 | **矢量路径反解（数字 PDF）** | 位图数字化 + 轴标定 | 矢量反解精度高一个数量级 |

> † 厂商/二手汇总数据，未独立复现；正文中所有具体数值均标注来源性质。

## 1. 先建立正确的"PDF 心智模型"

### 1.1 PDF 里到底有什么

| 层 | 内容 | 能拿到什么 | 拿不到什么 |
|---|---|---|---|
| Content Stream | 绘图指令（`Tj`、`re`、`c`、`Do`） | 字符、字形位置、路径、图像引用 | 段落、句子、表格、语义 |
| Font | 字体字典、`/ToUnicode` CMap、CID 表 | 字号、字族、粗斜、颜色 | 语义角色（标题/正文） |
| XObject | 位图（`/Image`）、嵌套表单（`/Form`，带变换矩阵与 z 序） | 原始分辨率的图 | 图里的"内容" |
| Structure Tree | Tagged PDF 的 `/StructTreeRoot` | **免费的阅读顺序与语义标签** | 老旧 PDF 通常没有 |

关键认知：**PDF 只声明"墨点画在哪里"，不声明"哪几个字组成一段"**。所以"解析"= 用几何 + 模型把墨点重新组装成结构。

### 1.2 三个必须先查的"廉价信号"

拿到 PDF 的第一件事，不是跑模型，是查三个字段——能省掉 80% 的模型调用：

```python
# 1) 是否 Tagged：有结构树就直接拿阅读顺序和 P/H1/Table 标签
has_struct = doc.xref_get_key(doc.pdf_catalog(), "StructTreeRoot")[1] != "null"
# 2) 字体表：看编码质量
page.get_fonts(full=True)   # (xref, ext, type, basefont, name, encoding)
# 3) 文本层健康度：字符数 / 乱码率 / 单字符 span 占比
raw = page.get_text("rawdict")
```

判读规则：

| 信号 | 含义 | 对策 |
|---|---|---|
| `ext == 'n/a'` 且 type 为 Type3 | 文字被"转曲"成矢量路径 | 文本层不可用 → 强制视觉通道 |
| `/ToUnicode` 缺失 + CID 字体 | 抽出来是乱码/私用区字符 | 自建 cmap 或用字体名反查；兜底 OCR |
| 大量单字符 span、字间距异常 | 排版引擎逐字定位（LaTeX/InDesign 常见） | span 合并需按 x 间距阈值，不能按空格 |
| 字符数 ≈ 0 但 drawings 密集 | 同上，转曲页 | 视觉通道 |
| 页面被一张大图覆盖 > 70% | 扫描页 | 视觉通道 |

### 1.3 总体流水线（六段）

```
[1 解剖] → [2 版面/阅读顺序] → [3 区域分类] → [4 分流识别] → [5 装配 IR] → [6 校验门]
   ↑ 原生文本/矢量路径/字体              ↑ 模型 or 规则         ↑ 三通道并行
```

- **[1 解剖]** 纯确定性：PyMuPDF/pdfminer.six/docling-parse 取出 **字符级的 bbox + 字体 + 颜色**，以及**矢量路径列表**。docling-parse 的思路最值得抄：它不做单词、不做行，只吐"字形单元格（glyph cell）"，把分组留到下游——这是正确的分层。
- **[2 版面]** 块级切分 + 阅读顺序。规则（XY-cut、Docstrum、Voronoi）+ 模型（DocLayout-YOLO、RT-DETR、LayoutLMv3）。
- **[3 分类]** 每个块打 type：title / paragraph / caption / table / figure / formula / header / footer。
- **[4 分流]** 表格走表格模型，图走图，公式走公式，文字走文字——**这是全篇的重点**。
- **[5 装配]** 统一 IR（见 §7.1），带来源 bbox 与 confidence。
- **[6 校验]** 每类内容一组可自动断言，失败的进人工队列（见 §7.5）。

## 2. 文字：版式、字体、多栏

### 2.1 可采用的解析思路

**A. 原生文本层提取（首选）**

| 工具 | 特点 | 适合 |
|---|---|---|
| PyMuPDF (`fitz`) | 最快；`rawdict` 给到每个 char 的 bbox+origin+font+size+flags+color；`get_drawings()` 给矢量路径 | 主力工具 |
| pdfplumber | 基于 pdfminer.six，char 级属性齐；表格 API 好用 | 表格/中间层 |
| pdfminer.six | 最细的布局分析（LTChar/LTTextLine/LTTextBox） | 需要精细控制时 |
| docling-parse | glyph cell + 多种坐标约定 + JSON 序列化 | 想做工业级 pipeline |
| `pdftotext -layout` | 空格对齐的纯文本，肉眼校验用 | 快速 diff |

**B. 字体即语义（这是最被低估的一招）**

不需要模型就能拿到 80% 的版式语义：先做字体统计，取正文的**众数字号与字族**作为基线。

| 观察 | 推断 | 处理 |
|---|---|---|
| size ≈ 众数 | 正文 | 按行合并成段 |
| size ≥ 1.2× 且 bold | 标题 | 按层级建 TOC（1.2×=H2，1.6×=H1） |
| size ≈ 0.85×，位于图下方/表上方 | 图注/表注 | 挂到对应 figure/table |
| 等宽字体（Courier/Consolas） | 代码、寄存器位域表、波形参数 | 保留空格，不折行 |
| 颜色非黑 | 超链接、强调、论文里的"本文结果" | 单独标记 |
| `flags` 含 superscript/subscript | 脚注标记、单位指数（mm²、10⁻⁹） | **必须还原**，否则数值单位全错 |
| Symbol / Wingdings 字体 | Ω、µ、°、±、≤ | 按字体查表映射，不能信 ToUnicode |

> EDA 场景的真实坑：`µA` 被读成 `mA`、`2.5×10⁻³` 的上标丢失变成 `2.5×10-3`、`−40` 的负号被读成连字符。这些不是"排版美观"问题，是**数值语义错误**。

**C. 多栏布局与阅读顺序**

分三步，顺序不能颠倒：

1. **先摘跨栏块**：宽度 > 0.7×版心宽的块（跨栏大图、通栏表格、页眉页脚）先摘出去，否则它们会被当成一栏，把左右两栏彻底打乱。
2. **再切栏**：对剩余区域做竖直空白投影（vertical whitespace projection）找 gutter；投影法对单栏/双栏/三栏都稳；不规则版面退回 XY-cut 递归。
3. **最后排序**：`(栏序号, y)` 字典序。脚注/侧栏按 y 兜底追加到页末。

模型路线：PaddleOCR-VL 用 RT-DETR 出区域 + 指针网络（pointer network）直接回归阅读顺序；DeepSeek-OCR 2 用 Visual Causal Flow——先让视觉 token 按学习到的阅读顺序重排成一维序列，再交给解码器，阅读顺序编辑距离从 0.085 降到 0.057†。

**D. 公式**：Nougat / UniMERNet / PP-FormulaNet / MinerU 的公式模型 → LaTeX。EDA 文档里公式少，但 `f = 1/(2πRC)` 这类必须保真。

### 2.2 适用场景

- 学术论文、教材、规格书正文、章节层级、脚注 → 原生文本 + 字体语义，质量最高、成本最低。
- Tagged PDF（政府/标准文档常见）→ 直接读结构树，**零模型成本**。
- 纯扫描件 → 只能视觉通道（OCR + 版面模型），见 §2.3。

### 2.3 局限性（失败模式清单）

| 失败模式 | 症状 | 缓解 |
|---|---|---|
| 文字转曲（outline） | `get_text()` 空但 PDF 看着有字 | 检测 Type3/无字体 → 强制 OCR |
| ToUnicode 缺失/CID 错乱 | 乱码、私用区字符 | 字体名 + 自定义 cmap；仍失败则 OCR 覆盖 |
| 逐字定位导致丢空格 | `Thequickbrownfox` | 按 x 间距/字宽比推断空格，不按字符判断 |
| 连字 fi/fl/ﬀ | `efficient` → `ecient` | 字体 ligature 表还原 |
| 跨栏图打乱顺序 | 段落跳到下一栏中间 | 先摘跨栏块（见上） |
| 双栏中的表格横跨两栏 | 被切成两半 | 表格检测在阅读顺序**之前**跑 |
| 扫描件 4pt 小字 | OCR 直接**编造**整段文字（Surya、PaddleOCR 均有此现象） | 字号 < 6pt 区域标记 low-confidence，进人工队列；不要相信输出 |
| 竖排/旋转文本 | 顺序颠倒 | 检测 text 方向角，分别处理 |

## 3. 图片

### 3.1 可采用的解析思路

**第一步：定位与无损提取（不要重新截图）**

| 来源 | 提取方式 | 注意 |
|---|---|---|
| 位图 XObject | `page.get_images(full=True)` + `doc.extract_image(xref)` | **拿原始分辨率**，别用渲染的 150dpi 版本 |
| 带 `/SMask` 或 `/Mask` | 必须把 alpha 通道合上 | 否则透明背景图变全黑 |
| JBIG2 / CCITT / JPEG2000 | PyMuPDF 多数可直接解；JPX 需 pillow | 扫描件常见，容易静默失败 |
| 纯矢量图（无位图） | `get_drawings()` 聚合 + `page.get_svg_image()` | EDA 图基本属于这类，见 §5/§6 |

**矢量图的聚类**：把 `get_drawings()` 返回的路径按 bbox 邻近/包含关系聚成"图形对象"，排除掉落在文本块内的路径（下划线、表格线），剩下的大块就是 figure。这比跑检测模型更准，因为它是**确定的**。

**第二步：图文关联（caption 绑定）**

这是"图有没有用"的分水岭——一张没有 caption 的图，对下游 LLM 的价值下降一个量级。

| 方法 | 做法 | 效果 |
|---|---|---|
| 规则 + 空间最近邻 | 正则 `^(Fig(ure)?|Tab(le)?|图|表)\s*\d+` + 同栏优先 + 图下/表上（中文期刊表题在上！） | baseline，覆盖 70–85% |
| PDFigCapX | 版面分析 + 显式图号标记 + 空间关联 | 经典可靠，被大量数据集构建流程使用 |
| FigEx（EMNLP 2025 Findings） | VLM 直接输出"子图 bbox ↔ 子图注"配对，BioSci-Fig 数据集 7,174 张复合图 | 解决**复合图/子图**场景 |
| MERMaid 的 VisualHeist | Florence-2 微调做 figure/caption/footnote 分割，>93% F1，比 PDFigCapX 高 28–75 个点† | 最脏的补充材料也扛得住 |

**第三步：理解与分类**

先分类再理解，不要一股脑丢给 VLM：

```
figure crop
  → 分类器（chart / photo / schematic / timing / fsm / block diagram / other）
  → 按类分流到 §5 / §6 / §7 的专用管线
```

分类可以用小模型（CLIP/微调 CNN，几毫秒）或一次便宜的 VLM 调用。**这一步的 ROI 极高**：把电路图误送进通用图表解析器，产出的是垃圾。

### 3.2 适用场景

- 论文/教材插图 → 切图 + caption + 类型分类 + 按类分流。
- 产品照片/显微图/版图 → VLM 描述 + 嵌入向量检索，不做精确解析。
- 复合图（a/b/c 子图）→ 必须走 FigEx 类子图切分，否则 caption 对不上。

### 3.3 局限性

| 问题 | 说明 |
|---|---|
| 复合图 | 一张图 6 个子图 + 1 段 caption，子图与子注的对应全靠模型；错一个后面全错 |
| 跨页/跨栏大图 | 被版面模型切成两半，或与正文混在一起 |
| 背景水印/扫描噪点 | 被当成图形内容 |
| `/SMask` 未合并 | 图全黑或全透明 |
| 无 caption / caption 极短 | 如 "Fig. 3."，无法关联语义 |
| 矢量图被裁剪（clip path） | `get_drawings()` 拿到的是未裁剪坐标，需应用 CTM 与 clip 求交 |
| 图内文字与外文混排 | 需图内 OCR，且要与外部 caption 区分 |

## 4. 表格

### 4.1 三条技术路线

| 路线 | 代表 | 原理 | 何时用 |
|---|---|---|---|
| **A 几何/线框** | Camelot（lattice/stream）、pdfplumber、Tabula | 有框线：取矢量线 → 求交 → 网格；无框线：文本 x 投影 + gap 阈值聚类 | 原生数字 PDF，**尤其三线表** |
| **B 结构识别模型** | TableFormer（Docling 内置）、SLANet/PP-StructureV3、UniTable、LORE | 图像 → 结构 token 序列（TableFormer 用 OTSL 语法）→ 还原 grid；再与 PDF 文本 bbox 对齐，**免 OCR 转录** | 无矢量线、或表格是图片 |
| **C 端到端 VLM** | PaddleOCR-VL-1.5、GLM-OCR、dots.ocr | 图 → HTML/Markdown | 复杂合并单元格、旋转表、跨页表；或 A/B 都失败时 |

**关键工程点**：原生 PDF 里表格的框线就是矢量路径——`get_drawings()` 里那些 `width` 很细的 `re`/`l`。用它们求交得到的是**精确网格**，比任何模型都准。**先试几何，再上模型**，能省一大截算力和错误率。

**TableFormer 值得单独说**：它输出 OTSL（一套受限语法），天然保证结构合法，然后**用预测的单元格 bbox 去和 PDF 里的字符 bbox 对齐**取文本——不做二次 OCR，因此文字零错误率。PubTabNet 上 TEDS 96.75（simple 98.5 / complex 95.0），CPU 上每表 2–6s、约 6GB RSS。

### 4.2 指标口径警告（很重要）

| 口径 | 含义 | 典型分数 |
|---|---|---|
| PubTabNet / FinTabNet（**裁剪后**的表格图） | 已经知道表在哪、表是什么 | TEDS ≈ 97（专家模型） |
| **文档内**全页（要先定位、可能无框线、可能旋转） | 真实工况 | TEDS 高 80s ~ 低 90s |

所以看到 "TEDS 96" 的宣传，先问是哪个口径。**跨口径比较是最常见的选型误判来源**。

### 4.3 适用场景

- 规格书参数表（Absolute Maximum Ratings、Electrical Characteristics、Timing）→ 几何 lattice，三线表极稳。
- 引脚表（Pin/Pin Name/Type/Description）→ lattice + 跨页续表继承。
- 论文中的结果对比表 → 多为无框线或半框线 → 模型或 VLM。
- 复杂合并/两级表头 → VLM（但需结构校验）。

### 4.4 局限性

| 失败模式 | 说明 | 缓解 |
|---|---|---|
| 合并单元格 / rowspan-colspan | 最常见错误源 | 输出 HTML（带 span 属性），不要输出扁平 CSV |
| 无框线表 | 只能靠空白推断，列边界模糊 | stream 模式 + 列数一致性校验 |
| 跨页续表 | 第二页没有表头 | 检测重复表头特征 / "continued" 关键词；继承表头 |
| 旋转 90° 宽表 | 行检测器直接失效 | 检测表格方向先旋转再识别 |
| 空单元格被填 | 模型"脑补"数值 | 空值断言：原文该位置无字符 → 必须为空 |
| 脚注符号 | `(1)` `*` `†` 与表外注释的对应丢失 | 建 footnote 关系边（MERMaid 用 RAG 做"条件 a"回链） |
| 单位在表头、值在单元格 | 数值无语义 | 表头单位解析 → 挂到每个 cell |
| 数值区间 `-40 to 125` / `2.5 (typ)` | 解析成单值 | 定义 value 结构：`{min, typ, max, unit, cond}` |

## 5. 电路图

### 5.1 信息构成（要抽出什么）

```
器件符号（MOS/BJT/R/L/C/Diode/OpAmp/受控源/Port/VDD/GND）
  ├─ 类型 + 朝向（旋转/镜像）  ← 决定 MOS 的 D/G/S/B 顺序！
  ├─ 位号 M1 / R2 / Q3
  └─ 参数 W/L=10u/1u、R=1k
连线（wire）+ 结点（junction dot）  ← "交叉" vs "连接" 必须区分
节点名 / 网络标签（VIN, VOUT, net12）
层次块（subckt 框 + 端口）
```

### 5.2 三条技术路线

**路线 A：传统 CV 几何流水线**

流程：二值化（Otsu）→ 连通域 → 骨架化 → 概率 Hough（PPHT）测线 → 模板匹配/HOG 认符号 → OCR 认位号。

- 优点：无训练数据、可解释、跑得快。
- 实测水平：Kelly & Cole 的方案在 15 张图上定位正确 166/194 个器件（85.6%）。手绘/白板场景可用。
- **致命弱点**：对绘图风格、旋转、缩放、线宽极度敏感；换一个厂商的图就崩。**不推荐作为生产方案**。

**路线 B：检测式 + 图重建（当前工程最优）**

```
① 符号检测      YOLOv8/v11（MOS/R/C/L/Diode…）        AMSNet: 97.1%
② 导线分割      U-Net / 连通域标记（CCL）
③ 文本检测识别  CRAFT + EasyOCR，或 VLM 做位号-框二部图匹配
④ 连接判定      引脚 bbox 边界外的像素 8-连通 BFS/DFS；小卷积核判 junction dot
⑤ 网表生成      元件 → SPICE 原语；引脚顺序按 bbox 朝向几何推断；缺省值标记
⑥ 校验          奇数度引脚组 → 人工；浮空节点 → 报错；GED 对参考网表
```

- 代表工作：**AMSNet**（YOLOv8 组件 + U-Net 导线，894→2686 张教材原理图，Spectre 网表）；**SINA**（YOLOv11 风格检测 + CCL 线推断 + EasyOCR/VLM 位号匹配，96.47% 网表生成准确率，节点正确率 ≈99.3%，比 Masala-CHAI 提升 2.72×†）；Hemker 等（YOLOv7 + L-CNN + EasyOCR，器件 mAP@0.95 ≥73%，但**引脚编号这类小字识别很差**）。
- 关键先验：**教材图比厂商 datasheet 图干净得多**。教材域训出来的模型直接上 datasheet，掉点会很厉害，需要目标域标注。

**路线 C：VLM 直接出 SPICE**

- 现状：GPT-4 认元件 ~90%，**认连接只有 ~45%**（AMSNet 论文的动机就是这个）。
- CircuitFormer 的做法值得学：用 Gemini 3 从教材原理图生成 31,341 条 netlist，**再用 ngspice 跑仿真做自动过滤**，收敛/语法失败的直接丢弃；人工抽检 50 例，95% 完美、元素级准确率 99.25%。
- 结论：**VLM 可以生成，但必须有一个"物理世界"的裁判**。没有仿真校验的 VLM 网表不能信。

### 5.3 适用场景

| 场景 | 推荐路线 |
|---|---|
| 教材/论文原理图，批量构建数据集 | B（必要时 C + 仿真过滤） |
| 厂商 datasheet（框图、典型应用电路） | B + 人工抽检；框图不必出网表，出"模块级连接图"即可 |
| 手绘/白板草图 | A（圆形度/骨架特征）或 C |
| 只有少数几张，要求准确 | C + 人工核对（最省时） |
| 需要进 EDA 工具做仿真 | B/C 出网表 + ngspice DC/AC 工作点校验（MOS 是否饱和、有无浮空节点） |

### 5.4 局限性

| 难点 | 为什么难 | 缓解 |
|---|---|---|
| 交叉 vs 连接 | 两根线相交不等于相连，只差一个 2px 的 dot | 显式训练/检测 junction；dot 半径与线宽比阈值 |
| 引脚序依赖朝向 | 同一个 MOS 符号翻转后 D/S 互换 | 检测时**必须回归朝向**（AMSNet 明确做了 rotate/flip） |
| 小字（引脚号、W/L） | 图内 4–6pt 文字 | 高 dpi 裁剪 + 专用小字模型；低置信度标记 |
| 参数在正文/表格里 | 图里只写 `M1`，W/L 在图注或表格 | 图-文-表跨模态关联（CircuitFormer 把整页一起喂给 VLM 正是为此） |
| 层次化 subckt | 一个框代表整个子电路 | 识别为黑盒 + 保留端口，不要试图展开 |
| 颜色语义 | 论文常用红色标"本文提出部分" | 保留颜色属性，作为弱语义特征 |
| 多页跨图 | 大电路拆两页 | 按位号连续性 + 端口名匹配合并 |
| 框图 vs 原理图 | 框图里是功能方块不是器件 | 先分类，别对框图跑器件检测 |

### 5.5 评价指标

- 元素计数/分类准确率（per-type counting）
- 连接判定（connection judgment，T/F）+ 连接识别（列出相连元件）
- **完整网表**：归一化网表编辑距离（NED）、图编辑距离（GED）
- 下游可用性：仿真是否收敛、工作点是否合理
- 参考基准：**AMSbench**（约 8,000 题，覆盖感知/分析/设计三级；其数据构建本身就用 MinerU 切图 + AMSnet 出网表——这条流水线可以直接抄）

## 6. 波形图

### 6.1 先分成两类，方法完全不同

| 类型 | 长相 | 要抽的东西 | 主要难点 |
|---|---|---|---|
| **模拟波形**（示波器截图、仿真波形、传输曲线） | 连续曲线 + 坐标轴 + 图例 + 网格 | `(x, y)` 数值序列 + 轴标定 + 单位 | 轴标定、多曲线分离、对数轴 |
| **数字时序图**（datasheet timing diagram） | 高/低电平方波 + 时间刻度 + 箭头标注 | `{signal: 边沿列表}` + `{标注: tsu/th/tco 与值}` | 信号名归属、边沿时刻、标注语义 |

### 6.2 模拟波形：矢量反解 >> 任何图像方法

**这是全篇最值得强调的一条工程技巧。**

数字 PDF 里，曲线不是像素，是**贝塞尔路径**。`page.get_drawings()` 返回的 `items` 里 `('c', p1, p2, p3, p4)` 就是三次贝塞尔控制点，`('l', p1, p2)` 是线段。直接把控制点还原成折线坐标，再对坐标轴做仿射/对数变换，就是数据点——**精度只受限于原图绘制精度，不受抗锯齿/分辨率影响**。

注意四个坑：
1. **CTM 与 clip**：路径坐标要乘当前变换矩阵；被 `W n` 裁剪的曲线需要与裁剪区求交。
2. **多曲线共用一条 path**：按 `color` / `width` / `dashes` 拆分。
3. **曲线被拆成上千条短线段**：按端点邻接做串接（tolerance 亚像素）。
4. **轴是独立 path**：先找出"最长水平/垂直线"做轴，再从轴上的刻度线（等距短线）反推比例尺——比 OCR 刻度数字更稳。

**位图数字化（扫描件/截图才用）**：

```
去网格（形态学开运算，长直线核）
→ 轴检测（Hough 长直线）
→ 刻度标定（等距刻度线计数 + 刻度标签 OCR 交叉验证；线性/对数/双轴分别处理）
→ 曲线分割（HSV 按颜色聚类；同色则骨架化后按连通性分离）
→ 采样（每列取中位 y，去异常点，平滑）
→ 单位换算 + 输出 CSV
```

误差源排序：**轴标定 > 曲线遮挡（图例压在曲线上）> 线宽/抗锯齿 > 图像倾斜**。先做透视校正（Homography）再谈精度。公开方案里 Image2Waveform 类系统报告 RMSE ≈ 2.7 像素 / 波形重建误差 ≈ 2.4%†。

### 6.3 数字时序图：本质是"离散事件抽取"

```
信号名区（左侧 label 列，OCR）→ 每行一条信号
每行波形：水平段（level）+ 垂直段（edge 时刻）+ 三态/高阻（中间电平）+ 总线（菱形/交叉）
时间轴：刻度线 + 数值 + 单位（ns/ps/µs），注意断轴（broken axis）
标注：双向箭头 + 文本（tsu / th / tco / tCLK）→ 结构化 {from, to, param, value}
```

输出应该是**机器可用的**：

```json
{
  "signals": [{"name":"CLK","edges":[{"t":0,"level":1},{"t":5,"level":0}]},
              {"name":"DATA","edges":[...]}],
  "annotations": [{"param":"t_su","from":"DATA","to":"CLK","value":2.3,"unit":"ns"}]
}
```

有了这个，可以直接生成 SDC 约束或 testbench（`$setup`/`$hold`），这才是 EDA 场景的终点。

**特别注意**：时序图上的数值（2.3 ns）通常**同时出现在表格里**。工程上应"**以表格为准，图只做定位与关系确认**"——图用于建立"哪个参数对应哪两个边沿"的映射，数值从表格取。这样能绕开最危险的一类幻觉。

### 6.4 适用场景

| 场景 | 推荐 |
|---|---|
| 原生 PDF 里的曲线（论文/教材/规格书） | **矢量反解**，一步到位 |
| 扫描的示波器截图 | 图像数字化 + 轴标定 |
| datasheet timing diagram | 边沿检测 + 信号名 OCR + 标注解析；数值以时序参数表为准 |
| 只要一段"这图说明了什么"的描述 | VLM（便宜、够用） |
| 要精确数值用于仿真/回归 | **禁止**用 VLM 出数值 |

### 6.5 局限性

| 失败模式 | 说明 |
|---|---|
| **VLM 数值幻觉** | 已观测：12 类分组柱状图输出 36 格错 23 格；VLM 会把"看起来合理"的数写进去。**任何来自图表的数字默认不可信**，必须与原文文字/表格交叉验证 |
| 对数轴 | 未识别对数轴 → 数值全错（误差可达数量级） |
| 双 Y 轴 | 左右轴混用 |
| 网格线密集 | 与曲线混淆，去网格时把曲线也削掉 |
| 图例压曲线 | 局部数据缺失，需插值并标记 |
| 动画/GIF | PDF 里是静态帧，信息缺失 |
| 时序图断轴 | 时间轴跳变处误连 |
| 多通道不同颜色 | 颜色相近时分离失败；需结合线型（实线/虚线） |

## 7. FSM 示意图

### 7.1 图形语法与目标输出

```
状态：圆角矩形 / 椭圆 / 圆形（内部写状态名，可能有 entry/exit 动作）
迁移：带箭头的有向边（可能带条件/动作标签，常换行）
初始态：实心小圆 + 指向初始状态的箭头
终止态：双圈
自环：从状态出发回到自身的弧
并行边：同一对状态间的多条边
```

**终点不是"描述这张图"，而是生成可执行的表示**：

| 输出 | 用途 |
|---|---|
| Graphviz DOT / Mermaid `stateDiagram-v2` | 可渲染、可 diff、可进文档 |
| JSON：`{states:[...], transitions:[{from,to,cond,action}]}` | 中间表示，供程序消费 |
| SystemVerilog / Verilog FSM（三段式） | 直接进 RTL |
| SMT / 断言 | 形式化验证 |

### 7.2 三条技术路线

**路线 A：传统 CV（形状先验）**

UW-Madison 的 automata-from-images 项目给了很实用的经验值：
- 状态检测：**填充后算 circularity > 0.9** 判为状态；再按半径 ≥ 最大半径/2 过滤假阳性（数字 0、字母 O）。
- 接受态：检测"一个状态完全包含另一个"。
- 迁移：骨架化 → 找三个端点（箭头尾部 + 箭头两翼）→ 中点/四分点反向外推，找最近的相交状态。
- 输入样例框：按 rectangularity + 颜色过滤，框内 OCR。
- 心得：手绘场景下 Hough/角点检测很脆，**形态学属性（圆度/矩形度/连通性）比几何拟合稳**。

**路线 B：检测 + 图重建（推荐）**

```
① 状态框检测（YOLO/DETR，类别=state/initial/final）
② 框内文本 OCR（或 VLM 读数）
③ 边检测（线段 + 箭头头部），或直接预测"两端所属状态"的关系头
④ 几何关联：边的两个端点落在哪个框 → from/to；起终点同框 → 自环
⑤ 边标签 OCR + 归属（沿边采样点最近的文本框；换行需拼接）
⑥ 图校验（见 7.4）
```

**FSMVision**（ISQED 2026）就是这个思路的多模态版：视觉解析 + 空间推理 + 语言 grounding 三件套，报告 **状态检测 99.00% / 迁移检测 99.01%**，并明确能直接转成可执行实现。

**路线 C：VLM 直接出 Mermaid/JSON**

- 优点：一行 prompt 就能出结构化结果，对小图（<10 状态）又快又准。
- 风险（实测常见）：**合并等价状态**、**漏掉并行边**、把注释文本误当迁移条件、条件文本归属错、自环丢失、编号/命名漂移。
- 用法：当 **draft 生成器**，然后用路线 B 的几何结果做**交叉校验**，不一致的进人工。

### 7.3 适用场景

| 场景 | 推荐 |
|---|---|
| 手绘/白板 FSM | A（圆度/骨架先验最稳） |
| 论文/教材印刷体 FSM（Graphviz/Visio 风格） | B；小图可 C 一次性搞定 |
| 密集自动布局（20+ 状态、边交叉严重） | B + 强制人工复核；纯 VLM 不可靠 |
| 层次状态机（子状态框嵌套） | B 需支持嵌套检测；先切子图再分别建图 |
| 需要直接出 RTL | B/C 出图 + 结构校验 + 模板化代码生成 |

### 7.4 局限性与校验

| 难点 | 说明 |
|---|---|
| 并行边 | 同 from/to 多条边，最容易被合并成一条 |
| 自环 | 常被漏检 |
| 条件文本跨行 | `A=1 &\nB=0` 需要按行距拼接 |
| 边交叉 | 视觉上交叉但语义无关，几何关联容易错 |
| 颜色/线型编码 | 实线=正常、虚线=异常路径，语义丢失 |
| 层次/子状态机 | 嵌套框，直接建图会漏掉层级 |
| 命名歧义 | `IDLE` vs `Idle` vs `idle`，需归一 |

**必须做的四条结构校验**（可全自动）：

1. **唯一初始态**：`count(initial) == 1`
2. **可达性**：从初始态 BFS，所有状态可达；不可达 → 报错
3. **标签非空**：除初始/终止外，所有迁移必须有条件（否则多半是漏 OCR）
4. **确定性检查**（若是 DFA）：同一 `(state, cond)` 不应有两个不同目标 —— 冲突即提示人工
5. **往返校验**：把输出渲染成图，与原图做结构相似度比对（视觉 diff），差异大的降级为低置信

## 8. 如何组合处理一份混合 PDF（核心章节）

### 8.1 统一中间表示（Document IR）

所有通道的输出必须落到**同一个 schema**，否则后期无法融合。建议最小可用集：

```jsonc
{
  "doc": { "pdf_id": "...", "pages": 12, "producer": "...", "encrypted": false, "tagged": false },
  "pages": [{
    "no": 1, "size": [595, 842], "rotation": 0,
    "profile": { "digital": true, "ocr_needed": false, "columns": 2, "lang": "en" },
    "blocks": [{
      "id": "p1-b7", "type": "figure",          // text|title|caption|table|figure|formula|header|footer
      "bbox": [72, 300, 523, 520], "z": 3, "ro": 12,   // ro = reading order
      "text": { "spans": [{ "t": "VDD", "font": "Arial", "size": 6.5,
                            "flags": "sup", "color": "#000", "bbox": [...] }] },
      "table": { "grid": [3, 5], "cells": [[{ "t": "VIL", "rowspan": 1, "colspan": 1 }]] },
      "figure": {
        "asset": "assets/p1_f7.png", "dpi": 300,
        "vector": "assets/p1_f7.svg",           // 原生矢量时保留，供后续反解
        "caption_id": "p1-b8",
        "graph": { "kind": "circuit|timing|fsm|plot", "payload": { /* 领域结构 */ } }
      },
      "src": { "channel": "native|vision|semantic", "model": "paddleocr-vl-1.5", "conf": 0.93 }
    }],
    "relations": [{ "from": "p1-b7", "to": "p1-b8", "rel": "caption_of" }]
  }]
}
```

三个设计要点：
- **`src.channel` 必填**：任何字段都要能回答"这条信息是谁给的"。冲突仲裁和事后审计全靠它。
- **`figure.vector` 保留 SVG**：数字 PDF 的图一定要留矢量版本，它是后续波形/电路反解的唯一高精度来源；只存 PNG 等于把信息永久烧掉。
- **`graph.payload` 与通用字段分离**：领域结构可以自由演化，不污染通用 IR。

### 8.2 分诊（triage）：先决定"这条内容由谁处理"

**页面级**

| 判据 | 结论 | 通道 |
|---|---|---|
| `nchars ≥ 20` 且无乱码 | 数字页 | Native |
| `nchars ≈ 0` 但有字体 | 转曲页 | Vision |
| `nchars ≈ 0` 且一张图覆盖 >70% | 扫描页 | Vision |
| 乱码率 > 5%（U+FFFD/私用区） | 编码坏 | Vision 覆盖 + Native 留档 |
| `tagged == true` | 结构树可用 | Native（免版面模型） |

**区域级**（每个 block 独立决策）

| 区域特征 | 通道 |
|---|---|
| 纯文本块 | Native（字体/坐标已有） |
| 表格 + 存在 ≥3 条细长矢量线 | Native 几何（Camelot/pdfplumber lattice） |
| 表格 + 无矢量线 | Vision（TableFormer）→ 失败则 Vision（VLM） |
| 矢量图（drawings bbox 聚成块） | Native 矢量 → 领域解析（波形/电路） |
| 位图 figure | Vision（分类 → 领域解析） |
| 公式块 | Vision（公式模型） |
| 6pt 以下小字 | 标 low-conf，**双重识别**（两个模型交叉） |

### 8.3 三通道的职责边界

| 通道 | 性质 | 只允许做 | 禁止做 |
|---|---|---|---|
| **Native**（PyMuPDF/docling-parse） | 确定性 | 字符、字体、坐标、矢量路径、表格线、结构树 | ——（它不会错，只会"缺"） |
| **Vision**（版面/表格/OCR/领域检测模型） | 概率性 | 定位、分类、结构、转录 | 推断未出现的内容 |
| **Semantic**（VLM/LLM） | 生成性 | 打标签、写描述、归一命名、补"这张图是什么类型" | **生成数值、生成拓扑、补全缺失的连接** |

一句话记住：**Semantic 通道只允许"起名字"，不允许"造事实"。**

### 8.4 冲突仲裁规则

| 冲突类型 | 优先级 |
|---|---|
| 数值（`2.3` vs `23`） | Native 字符 > OCR > VLM 生成；VLM 结果永不覆盖前两者 |
| 结构（表格列数、图形边框） | Native 矢量线 > 模型检测框 > VLM 输出 |
| 阅读顺序 | Tagged 结构树 > 版面模型 > 规则 |
| 图类型标签 | VLM 语义 > 小分类器（语义判断本来就是 VLM 强项） |
| 文本内容 | Native 与 OCR 都成功时取 Native；OCR 仅在 Native 缺失/乱码时启用 |

### 8.5 融合与关联

混合 PDF 的价值 60% 来自**关联**，不是单块解析：

```
figure ──caption_of──> caption ──mentions──> paragraph
   ↑                                          │
   └───────── refers_to（"如图 3 所示"）────────┘

table ──footnote_of──> 页脚注释
table ──continues──> 下一页 table（跨页续表）
circuit ──params_from──> 正文/表格（W/L、偏置电流）
timing  ──values_from──> 时序参数表（tsu/th/tco）
```

- **图注绑定**：§3.1 第二步。
- **正文回链**：正则 `(Fig(ure)?|图|Tab(le)?|表)\s*(\d+)([a-z])?` → 建边。这一步让"这张电路图在讲什么"有了上下文。
- **脚注关联**：上标标记（`flags` 含 sup）→ 页脚文本，按编号匹配。datasheet 的 `(1)(2)` 条件注释全靠它。
- **跨页续表**：表头特征重复 + "continued"/"续表" 关键词。
- **图→表参数引用**：这是 EDA 场景最关键的一跳（波形图的数值来自表、电路图的 W/L 来自表），做好了整个数据集才"可仿真"。

### 8.6 质量门（QA Gate）

每一类内容配 3–5 条可自动断言，失败即降级/入人工队列。这是把"能用"变成"可信"的地方。

| 类型 | 自动断言 |
|---|---|
| 文字 | 字符数 > 0；乱码率 < 1%；段落长度分布无异常峰值；标题层级单调；`<6pt` 区块标记 low-conf |
| 表格 | 每行列数一致；`min ≤ typ ≤ max`（若存在三列）；单位可解析；数值与原文 token 逐字比对；空单元格在图里确实为空 |
| 图片 | caption 存在且前缀合法；图注与图同页/相邻页；子图数 = caption 里 (a)(b)(c) 数 |
| 电路 | 无浮空节点；每个器件至少 2 个引脚连通；网表能过语法检查；ngspice DC 收敛；MOS 有工作在饱和区的可能 |
| 波形 | 轴标定至少 2 个参考点；曲线点数 > 阈值；数值落在轴范围内；与表格参数交叉一致（±容差） |
| FSM | 唯一初始态；全状态可达；迁移标签非空；DFA 确定性；往返渲染结构相似度 > 阈值 |

### 8.7 性能与成本

| 手段 | 收益 |
|---|---|
| 页面级并行 + 区域级并行 | 线性加速；注意 GPU 批处理按 ROI 尺寸分桶 |
| ROI 裁剪再送模型 | 比整页送模型省 3–10× 算力，且精度更高（等效提高分辨率） |
| 缓存（page_hash + model_version） | 重跑不重复付费；模型升级时精确失效 |
| 小模型先跑，大模型只兜底失败区域 | 0.9B 级模型（PaddleOCR-VL/GLM-OCR）跑 95%，剩下 5% 才用大模型 |
| Native 优先 | 数字 PDF 的文字/表格/矢量**零模型成本** |

### 8.8 伪代码骨架

```python
def parse_pdf(path):
    doc = fitz.open(path)
    ir = {"pages": []}
    for page in doc:
        prof = profile(page)                       # §1.2 三个廉价信号
        native = extract_native(page)              # 字符+字体+矢量路径+表格线
        blocks = layout_blocks(page, native)       # 规则优先，必要时模型
        for b in blocks:
            route = triage(b, prof)                # §8.2
            if   route == "native_text":  b.text = native.text_in(b.bbox)
            elif route == "native_table": b.table = grid_from_vector_lines(b)
            elif route == "vector_fig":   b.figure.vector = svg_of(b); b.figure.graph = domain_parse(b)
            elif route == "vision":       b = vision_parse(page, b)       # 渲染 ROI → 模型
            elif route == "semantic":     b = vlm_enrich(page, b)         # 只加标签/描述
        bind_captions(blocks); link_refs(blocks); link_footnotes(blocks)
        ir["pages"].append({"blocks": blocks, "relations": collect_relations(blocks)})
    qa_report = run_gates(ir)                      # §8.6
    return ir, qa_report
```

> 这是**骨架示意**，不是可直接上线的库；真实实现需要处理 CTM/clip、加密、旋转、异常字体等边界（见 §2.3）。

## 9. 选型建议

### 9.1 按场景

| 场景 | 组合 | 说明 |
|---|---|---|
| **A. 通用文档 → Markdown（RAG/知识库）** | PaddleOCR-VL-1.5（或 GLM-OCR）单模型端到端 | 不需要自建。中文/表格多选 GLM-OCR（Table-TEDS 93.96 vs 84 左右†）；要吞吐和 MIT 许可选 DeepSeek-OCR 2；纯 CPU/离线选 Docling |
| **B. EDA datasheet 全要素结构化** | PyMuPDF（Native）+ MinerU/PaddleOCR-VL（版面与文字）+ 自建领域层（表格几何 + 电路/波形/FSM 解析）+ 校验门 | **没有现成方案**，必须自建；但通用层可以直接用开源省掉 70% 工作量 |
| **C. 论文/教材图表数据集** | DocLayout-YOLO（切图）+ 类型分类器 + 领域模型（AMSNet/FSMVision 路线）+ 仿真/渲染校验 | AMSbench、CircuitFormer 的数据构建流程可以直接借鉴 |
| **D. 纯扫描历史文档** | PaddleOCR-VL-1.5（支持多边形框：倾斜/褶皱/弯曲/暗光）+ DeepSeek-OCR 兜底 | 别用 Docling 硬扛扫描件，准确率明显更低 |
| **E. 少量高价值文档（几十页）** | VLM（Gemini/GPT/Claude）+ 人工核对 | 自建不值当 |

### 9.2 三档预算方案

| 档位 | 硬件 | 组件 | 能力边界 |
|---|---|---|---|
| **轻** | Mac（M 系列）/ CPU | PyMuPDF + Docling + 规则表格 | 数字 PDF 全要素（除图语义）；¥0；可离线 |
| **中** | 单张 A100/A800 40G | PaddleOCR-VL-1.5 或 MinerU 2.5 + 微调 YOLO（器件/状态框）+ ngspice | 覆盖 A–D；领域模型需 500–2000 张标注图 |
| **重** | 多卡 + 云 API 兜底 | DeepSeek-OCR 2 批处理 + VLM API（难例）+ 人工复核队列 | 高吞吐、高召回；成本主要在人工复核 |

### 9.3 关键取舍清单

| 维度 | 注意点 |
|---|---|
| **许可** | Docling MIT、PaddleOCR Apache-2.0、DeepSeek-OCR MIT；**MinerU 历史上是 AGPL-3.0，商用前务必核对当前 LICENSE**；GLM-OCR 需核实 |
| **数据合规** | datasheet / 版图 / 未发布产品资料可能受 NDA 约束。**这类内容一律走本地部署**，不要送云 API |
| **可追溯** | 每个字段带 `src.channel` + bbox；没有来源的数值不允许进数据库 |
| **版本漂移** | 模型升级会静默改变输出。缓存键必须含 model_version，并保留回归集 |
| **中文排版** | 中文表题在图**上方**、图题在下方；中文没有空格分词；全角/半角标点混用 |
| **字体依赖** | 国产 PDF 常嵌特殊字体（方正/汉仪），字形映射错乱率高；优先 OCR 交叉验证 |

### 9.4 落地路线图

| 阶段 | 目标 | 验收 |
|---|---|---|
| **P0（1–2 周）** | Native 解剖层：文本+字体+坐标+矢量路径+表格线，统一 IR | 在 50 页金标上，文字 CER < 0.5%，表格网格与人工一致率 > 90% |
| **P1（2–4 周）** | 分诊 + 通用层（PaddleOCR-VL / Docling 接入）+ 图注绑定 | figure-caption 配对 F1 > 0.9；阅读顺序人工抽检通过 |
| **P2（4–8 周）** | 领域层：波形矢量反解 + 时序图 + FSM（先做矢量/印刷体） | 波形 RMSE < 1% FS；FSM 状态/迁移 P/R > 0.95 |
| **P3（8–12 周）** | 电路图 → 网表 + 仿真校验 + QA 门 + 人工队列 | 网表 NED < 0.1；ngspice 收敛率 > 80% |

顺序原则：**先做确定性最强的（Native），再做概率性最高的（电路拓扑）**。每一步都能独立产生价值，不会因为最后一步难而全盘卡住。

## 10. 评价与基准：别信榜单，自建金标

### 10.1 为什么不信公开榜单

1. **口径不一致**（裁剪表 vs 文档内表，差 10 个 TEDS 点）。
2. **分布不一致**：OmniDocBench 覆盖书籍/报告/论文/试卷，但**不含电路图、时序图、FSM**。你在 EDA 上的实际得分可能比榜首低 20 分。
3. **二手数据**：本文中带 † 的数字来自厂商博客/聚合站，未独立复现；选型时必须自己跑一遍。

### 10.2 建议的自建基准

- **规模**：50–100 页，覆盖六类内容各 ≥10 例，包含 3 种以上来源（教材/论文/datasheet）、2 种以上质量（数字/扫描）。
- **标注**：区块 type + bbox、表格 grid、图注配对、领域结构（网表/波形 CSV/FSM JSON）。
- **指标分层**：

| 内容 | 指标 |
|---|---|
| 文字 | CER / WER + 阅读顺序编辑距离 |
| 表格 | TEDS / TEDS-Struct + 单元格 F1 + 结构错误类型分布 |
| 图 | 类型分类 acc；caption 配对 P/R |
| 电路 | 元件计数 acc、连接判定 P/R、网表 NED |
| 波形 | 轴标定误差、采样 RMSE（%FS） |
| FSM | 状态/迁移 P/R、图编辑距离 |

- **最后一条建议**：报告**失败模式分布**，而不是单一分数。"表格错了 8%，其中 7% 是合并单元格"比"TEDS 88"有用一百倍。

## 11. 风险清单

| 风险 | 后果 | 对策 |
|---|---|---|
| **数值幻觉** | 图上"看起来合理"的数字进了数据库，下游仿真/选型全错 | 数值只走 Native/OCR；VLM 输出数值一律拒收；与表格交叉验证 |
| **拓扑幻觉** | 电路网表多一条/少一条连接，仿真照样收敛，但电路是错的 | 只信几何重建；VLM 结果必须与几何结果一致；浮空节点/奇数度检查 |
| **许可风险** | AGPL 传染、商用受限 | 选型时逐个核对 LICENSE；关键路径优先 MIT/Apache |
| **数据出境** | NDA 违约 | 本地部署；云 API 仅用于公开资料 |
| **版权** | 图表再分发侵权 | 只存结构化结果 + 引用定位，不批量再分发原图 |
| **可复现性** | 模型静默升级导致结果漂移 | 固定版本 + 回归集 + 缓存键含版本 |
