# 每天 1 小时面试练习手册（配套 24 周课程）

> 适用前提：每天 3 小时 = 2h 学习（按 `llm-career-course-design.md` 课程）+ **1h 面试练习（本手册）**。
> 核心原则：**面试练习不是课程结束后的冲刺，而是与学习同步的复利积累**——
> 当天学的内容，48 小时内必须能用嘴讲出来；讲不出来的就是没学会。

---

## 一、每日 1 小时的周节奏（不要每天做同一件事）

| 星期 | 形式 | 60 分钟分配 |
|------|------|-------------|
| 一 | **八股问答**（本周学习内容） | 30min 抽题录音作答 → 20min 回听复盘 → 10min 修正答案笔记 |
| 二 | **手撕题** | 45min 限时手写（白板/纸/空编辑器）→ 15min 对照参考实现找差距 |
| 三 | **项目深挖** | 20min 自问自答（5 层 why）→ 25min 录音作答 → 15min 复盘 |
| 四 | **八股问答**（题库弱项） | 同周一，但题目来自"卡壳/未答"状态池（见 §四） |
| 五 | **自我介绍 + 行为面试** | 15min 自我介绍录音 → 15min 复盘 → 30min 行为题（STAR）1 道 |
| 六 | **错题重练 / 半月模拟** | 单周：本周卡壳题全部重答一遍；双周：60min 完整模拟面试（见 §五） |
| 日 | **复盘 + 动态调整** | 30min 填写本周评分表 → 30min 更新题库状态、定下周重点 |

**为什么这样安排**：八股考"记住没有"，手撕考"肌肉记忆"，深挖考"真懂假懂"，
自我介绍考"表达结构"——四种能力用四种训练形式，每天换着练比每天背题效率高得多。
周六的"错题重练"是闭环关键：**只练新题不重练错题，等于白练**。

## 二、五种模拟面试形式的具体做法

### 2.1 自我介绍（每周五，从 W1 就开始）

- **准备两个版本**：1 分钟版（电话筛选用）+ 3 分钟版（正式面试开场用）。
- 3 分钟版结构（逐句写出来，不要即兴）：
  1. 背景一句话（"X 年 EDA 工程师，C++ 大型系统与性能优化"）；
  2. 转型动机一句话（**必须正面**："推理系统是我现有能力的延伸"，不是"EDA 没前途"）；
  3. 核心能力三点（C++/CUDA/推理优化，各配一个数字）；
  4. 项目钩子一句话（"最近在用 vLLM 给 EDA 知识库做部署，压测到 X QPS"）——
     **钩子是设计出来的**：你埋什么钩子，面试官就追问什么，等于你出考题。
- 迭代节奏：每 4 周根据课程进度重写一次钩子（W12 换成 CUDA 项目、W20 换成旗舰项目）。

### 2.2 项目深挖（每周三，从有第一个项目开始）

对每个项目预写 **5 层 why 问答链**（以 mini-infer 为例）：

```text
L1 你做了什么？        → 一句话 + 量化结果
L2 为什么这么设计？    → "为什么选 paged 而不是连续预分配？"（碎片问题 + 数据）
L3 还有什么方案？      → "考虑过 swap/recompute 吗？trade-off 是什么？"
L4 怎么验证的？        → "cache/no-cache 一致性怎么测的？atol 取多少？为什么？"
L5 最大的坑 / 重做会怎样？ → 真实踩坑故事（提前准备 2 个，含数据）
```

规则：**L4/L5 必须基于真实实验记录回答**——编造的细节在第二轮追问就会崩。
课程里每个项目的 benchmark 报告、golden test 就是 L4 的弹药库。

### 2.3 八股问答（每周一/四）

- 不是"看答案"，是**"听问题 → 立刻口头作答 → 再对照答案"**。看懂 ≠ 能讲。
- 每题作答限时 2–3 分钟，要求**结论先行**（第一句直接给答案，再展开）。
- 题库建设与状态流转见 §四。

### 2.4 手撕题（每周二）

| 阶段 | 题目池 | 限时 |
|------|--------|------|
| W1–6 | Python 基础题 + LeetCode hot 100（每周 1–2 题） | 30min/题 |
| W7–15 | **手撕 attention（numpy/torch）、数值稳定 softmax、top-k sampling**、KV cache 读写逻辑 | 45min |
| W16–24 | 手撕 attention 进阶（带 mask/GQA/RoPE 变体）、CUDA 伪代码、简单 CUDA kernel | 45min |

要求：在**无自动补全的环境**写（白纸或纯文本编辑器），写完再跑——
面试现场没有 IDE。手撕 attention 是大模型岗真实高频题，目标 20 分钟内无参考写出。

### 2.5 完整模拟面试（双周六，W16 起改每周）

60 分钟全真流程（严格计时）：

```text
0–3min   自我介绍（3 分钟版）
3–25min  项目深挖（抽 1 个项目，自问 5 层 why 全链）
25–45min 八股 6–8 题（从题库随机抽，覆盖 ≥3 个主题）
45–60min 手撕 1 题 或 系统设计简答（"设计 X QPS 推理服务"）
```

W20 后升级为**真人模拟**：找同行朋友 / 牛客等平台付费模拟，每月 ≥1 次——
自练无法模拟"被追问时的压力"，真人反馈是最贵的输入。

## 三、大模型方向面试题库（按课程进度分阶段解锁）

**建库方法**：每周日从本周 2h 学习内容中提炼 5–8 道题入库（自己出题自己答，出题即复习）。
以下是各阶段的种子题与考察点：

### 阶段一（W1–6）：Transformer 与 PyTorch

- 手写 attention 的完整公式与 shape 流；为什么要除 √d_k？
- softmax 为什么要减 max？溢出会发生什么？
- RoPE 的相对位置性质怎么来的？和绝对位置编码的区别？
- pre-norm vs post-norm 的差异与原因；RMSNorm 省了什么？
- GQA/MQA 为什么省 KV cache？省多少（会算数）？
- `no_grad` vs `inference_mode`；`view` vs `reshape`（stride 层面）。

### 阶段二（W7–15）：推理优化（主攻，权重最高）

- 为什么 prefill 是 compute-bound、decode 是 memory-bound？（**必考，要求能现场推导算术强度**）
- KV cache 显存公式推导；7B/70B 各算一遍。
- continuous batching 相对静态 batching 的收益来源；调度器每个 iteration 做什么决策？
- PagedAttention 解决什么问题？block table 如何寻址？碎片率多少？
- FlashAttention 的核心思想（tiling + online softmax）；为什么不物化 attention 矩阵？
- 投机解码原理；接受率与加速比的关系；为什么用小模型 draft？
- INT8/FP8/AWQ/GPTQ 的 trade-off；量化为什么对 decode 帮助大？
- TTFT/TPOT 定义；batch size 对二者分别什么影响？（会画曲线）
- CUDA 基础：warp/内存层级/coalescing/shared memory tiling；手写 kernel 的优化路径。

### 阶段三（W16–24）：训练微调 + 应用 + 系统设计

- LoRA 原理与显存账；QLoRA 与全参微调的差异（**用你 W17 的对照实验数据回答**）；
- FSDP 怎么切分？通信在哪里发生？TP/PP/DP 的区别与适用场景；
- 继续预训练的数据配比原则；灾难性遗忘怎么缓解；
- RAG 全链路：chunking 策略、混合检索、rerank 的价值、评测怎么做；
- 系统设计题 2 道背熟：「设计 X QPS LLM 推理服务」（用 mini-infer 架构 + 压测数据）；
  「设计企业知识库问答系统」（用 EDA 智能助手项目）。

## 四、自我录音复盘方法（本手册的核心动作）

### 4.1 录音流程

1. 手机录音，**不看稿直接答**（模拟真实压力）；
2. 答完立刻回听（不要攒到周末，记忆还热）；
3. 按下表逐项打分（1–5 分），记入跟踪表：

| 维度 | 检查点 | 常见失分表现 |
|------|--------|--------------|
| 结论先行 | 第一句是否直接给答案？ | 铺垫 30 秒还没进入正题 |
| 结构 | 是否有"第一/第二/第三"的显式结构？ | 意识流，讲到哪算哪 |
| 准确 | 术语、公式、数字是否说对？ | "大概是 O(n²) 吧"（不确定语气） |
| 量化 | 是否有具体数字支撑？ | "性能提升很多"（应说"2.3x，batch=8 实测"） |
| 流畅 | 卡顿 >3 秒的次数 | 超过 2 次即不合格 |
| 时长 | 单题 2–3 分钟 | <1 分钟说明深度不够，>4 分钟说明不会收口 |

4. **当天重答一遍同一题**（应用修正后），两次录音对比——这是进步最快的一环。

### 4.2 题库状态表（动态调整的数据基础）

每题维护四个状态之一，放在简单表格/Anki 里：

```text
状态流转：未答 → 卡壳（录音复盘 <3 分）→ 合格（3–4 分）→ 熟练（连续 2 次 ≥4 分）
复习间隔：卡壳题 1 天后重答；合格题 3 天；熟练题 14 天后抽检
```

| 题目 | 主题 | 状态 | 最近得分 | 下次复习 |
|------|------|------|----------|----------|
| 为什么 decode 是 memory-bound | 推理优化 | 合格 | 4 | 07-30 |
| LoRA 显存账 | 微调 | 卡壳 | 2 | 07-28 |
| … | | | | |

### 4.3 每周评分表（周日 30 分钟填）

```text
本周八股：抽答 __ 题，平均 __ 分；卡壳题 __ 道（列出）
本周手撕：__ 题，限时内完成 __ 题
本周深挖：L4/L5 是否有真实数据支撑？是/否
自我介绍：最新版本钩子是否已更新？是/否
下周重点（低分项）：__________
```

## 五、动态调整机制（练什么由数据决定，不由感觉决定）

### 5.1 三条调整规则

1. **弱项优先**：周日评分表中得分最低的形式，在下周多排 1 次（如八股最弱 → 周一/四/六都排八股）。
2. **卡壳题不过夜（48 小时规则）**：状态为"卡壳"的题，48 小时内必须重答并回到题库；
   同一题卡壳 3 次 → 说明对应知识没学会，**回到 2h 学习侧补理论**，而不是继续硬背。
3. **阶段重心迁移**：面试练习内容跟着课程门禁走——

| 课程阶段 | 面试练习重心 | 时间分配（1h 内） |
|----------|--------------|-------------------|
| W1–6（G1 前） | Transformer 八股 + 自我介绍定型 + Python 手撕 | 八股 50% / 手撕 30% / 表达 20% |
| W7–15（G2 前） | **推理优化八股 + 手撕 attention/softmax** + 项目 L1–L3 | 八股 40% / 手撕 40% / 深挖 20% |
| W16–22（G3 前） | 微调/分布式 + 项目 5 层 why 全链 + 系统设计 | 深挖 40% / 八股 30% / 系统设计 30% |
| W23–24（冲刺） | 全真模拟为主：双周六改每周，加入真人模拟 | 模拟 60% / 错题 40% |

### 5.2 两个不要

- **不要背标准答案**：面试官听过 100 遍的答案拿不到高分。每道八股题的答案里
  必须嵌入一个"你自己的东西"——实验数据、踩坑故事、源码行号。这正是课程要求
  所有结论附数据的原因。
- **不要在状态差的时候录音**：录音复盘的价值依赖真实水平发挥；疲劳时改做
  题库整理/答案笔记修订（低强度任务），但 1 小时不挪用给学习侧。

## 六、与课程门禁的对齐检查点

- **G1（W6 末）**：Transformer 主题 20 题录音自测 ≥80% 合格；自我介绍 1min/3min 版定稿。
- **G2（W15 末）**：推理优化主题题库 ≥40 题，"熟练"占比 ≥50%；手撕 attention ≤20min 无参考完成。
- **G3（W24 末）**：全题库 ≥100 题，"卡壳"清零；3 个项目 5 层 why 全链可脱稿；3 轮模拟面试通过（含 ≥1 次真人）。
