# W1 · 执行模型与硬件架构

> 目标：任何一道架构题，你都能从"warp 是调度单位、SM 是资源单位"这两句话推出来，而不是背答案。

---

## 一、面试官在筛什么

W1 的题几乎都不是知识题，而是**推理题**。面试官给你一个怪异参数（35 个线程的 block、奇数大小的 grid、每线程 200 个寄存器），看你能不能从硬件约束推出后果。

他真正想确认三件事：

1. 你知道**调度粒度是 warp，不是 thread**。
2. 你知道**SM 的资源是共享的、有上限的**（寄存器、shared memory、warp 槽、block 槽）。
3. 你知道 **GPU 的性能来自 TLP（线程级并行）+ 超额订阅来隐藏延迟**，而不是 CPU 那套乱序执行和分支预测。

这三条答不出来，后面所有优化题都会塌。

## 二、概念精讲

### 2.1 硬件层级：从卡到 lane

```
GPU (A100: 108 SM)
 └─ GPC (Graphics Processing Cluster)
     └─ TPC (Texture Processing Cluster)
         └─ SM (Streaming Multiprocessor)   ← 资源分配与调度的真正单位
             ├─ 4 × Processing Block (partition)
             │    ├─ 1 × Warp Scheduler + Dispatch Unit
             │    ├─ 16 × FP32 Core (GA100 共 64/SM)
             │    ├─ 16 × INT32 Core
             │    ├─ 8 × FP64 Core
             │    ├─ 1 × Tensor Core (第三代，共 4/SM)
             │    └─ 4 × SFU
             ├─ Register File：256 KB（64K × 32-bit，SM 内所有线程共享）
             └─ 192 KB 统一 L1 / Shared Memory（可配置切分）[R4]
```

**内存里要记住的一句话**：partition 是发射单位，SM 是资源单位。一个 warp 一旦被分配到某个 partition 的 scheduler 上，它整个生命周期都在那个 partition 上跑。

**A100 的 SM 与消费级 Ampere（GA102）的关键差异**：GA100 每 SM 64 个 FP32、每 partition 16 个；GA102 每 SM 128 个 FP32、每 partition 32 个（其中 16 个是 FP32/INT32 复用）。看到"每 SM CUDA core 数"这个指标时，一定要问清是哪颗芯片——这是 AI 芯片岗位面试官最爱设的坑。

### 2.2 两级并行：Grid → Block → Thread

| 层级 | 数量级 | 物理映射 | 能否通信 |
|---|---|---|---|
| Thread | 百万级 | 一个 lane | 通过 shared memory / shuffle |
| Block | 万级 | **绑定到一个 SM**，不迁移 | block 内可 `__syncthreads()` |
| Grid | 1 个 kernel 1 个 | 分布到所有 SM | 不能（除 cooperative groups 的 grid sync） |

硬上限（CC 8.0）[R2]：

| 项 | 上限 |
|---|---|
| 每 Block 线程数 | 1024 |
| Block 维度 | 最多 3 维；x/y ≤ 1024，z ≤ 64 |
| Grid 维度 | 最多 3 维；x ≤ 2³¹−1，y/z ≤ 65535 |

**索引公式（白板必写对）**：

```cpp
int x = blockIdx.x * blockDim.x + threadIdx.x;
int y = blockIdx.y * blockDim.y + threadIdx.y;
int z = blockIdx.z * blockDim.z + threadIdx.z;
```

`blockxIdx` 从 0 开始，`blockDim` 是每块的实际线程数——**如果你 launch 时传的 blockDim 和你 kernel 里假设的不一致，索引就全错**。

### 2.3 Warp：为什么是 32

一个 warp = 32 个连续线程（`threadIdx.x` 相邻，跨 warp 边界重新开始）。这 32 个线程**共享一条取指/译码通路**，在同一周期执行同一条指令，作用在 32 个不同的操作数上。

- Warp 是**调度和发射的最小单位**。SM 的 warp scheduler 每周期从就绪 warp 里挑一个，发射一条指令。
- Warp 是**寄存器分配和占用计算的单位**。
- A100：64 warps/SM ÷ 4 partition = 每 scheduler 16 个候选 warp。这就是"延迟隐藏"的库存。

**35 个线程的 block 会怎样**（经典题）
`ceil(35/32) = 2` 个 warp，硬件按 2 个 warp 分配资源。第二个 warp 只有 3 条 lane 有效，另外 29 条被 mask 关闭，但**寄存器、warp 槽、发射周期一样要占**。所以 block 大小应该是 32 的整数倍——这不是"建议"，是资源利用率的硬约束。

### 2.4 SIMT vs SIMD（这题答错的人很多）

| | SIMD | SIMT |
|---|---|---|
| 谁写代码 | 程序员显式写向量类型（如 `float4` / AVX intrinsic） | 程序员写**标量线程**代码，硬件自动捆绑 |
| PC | 全 lane 共享一个 PC | Volta 起**每线程独立 PC** |
| 分支 | 无法 per-lane 分支，只能靠 mask | 可以 diverge 后再 reconverge |
| 寻址 | 通常要求连续/规律 | 每线程可独立寻址（gather/scatter） |
| 状态 | 无 per-lane 架构状态 | 每线程完整寄存器上下文 |

**标准答法**："SIMT 是 SIMD 的可编程性改进：硬件把 32 个独立线程捆绑成 warp 并行发射，对外表现像 SIMD，但每个线程有自己的寄存器和程序计数器，所以能写普通标量代码、能处理分支和离散寻址。代价是分支会被串行化执行。"

**追问：Volta 的 Independent Thread Scheduling 有什么实际影响？**
答：在此之前，warp 内所有线程共享一个 PC，分支必须等所有路径执行完才 reconverge。Volta 之后每线程有独立 PC，编译器用 `BSSY`/`BSYNC` 显式管理 reconvergence 点，允许 warp-synchronous 代码（依赖隐式同步的老代码）不再安全——**必须用 `__syncwarp()` 替代"靠 warp 内自然同步"的假设**。这也是 2017 年后很多老 CUDA 代码出现诡异 bug 的原因。

### 2.5 Warp Divergence：代价到底有多大

```cpp
// 交错分支：最坏情况
if (threadIdx.x % 2 == 0) { /* 路径 A，16 条 lane 有效 */ }
else                      { /* 路径 B，16 条 lane 有效 */ }
```
执行方式：先跑 A（B 的 16 条 lane 被 mask），再跑 B（A 的 16 条 lane 被 mask）。**总时间 ≈ 2 × 单路径时间，有效 lane 利用率 50%**。

关键结论（面试要点）：
1. **代价 = 各分支路径执行时间的总和**，不是线程数。如果 `if` 里只有 1 条指令、`else` 里有 1000 条循环，那 1 条分支的代价可以忽略。
2. **分支条件只依赖 `blockIdx` / `threadIdx` 且 warp 内一致**（warp-uniform）时，**没有 divergence**。例如 `if (threadIdx.x < 128)` 在 block=256 时，warp 0–3 全真、warp 4–7 全假 —— 每个 warp 内部一致，零代价。这是**边界检查几乎免费**的原因。
3. **数据相关分支**（`if (a[i] > 0)`）才是真正的杀手，因为 warp 内不可预测。

规避手段：把分支改写成**无分支的算术/谓词**（`x = cond ? a : b` 编译成 `SEL`，不是分支）、把同类数据聚在一起（排序/分桶，让 warp 内取到相似值）、或用 `__ballot_sync` 先统计再决定路径。

### 2.6 Occupancy：四个限制因素与手算

**定义**：occupancy = 每 SM 实际活跃 warp 数 / 每 SM 最大 warp 数（64）。官方 API 与计算器见 [R1] 的 Occupancy 章节与 [R16]。

四个限制因素，取最小值：

| 限制 | A100 上限 | 单 block 占用 |
|---|---|---|
| 线程 | 2048 / SM | `ceil(blockDim / 2048)` |
| Warp | 64 / SM | `ceil(blockDim/32 / 64)` |
| Block 槽 | 32 / SM | 1 |
| 寄存器 | 65536 / SM | `blockDim × regsPerThread`（按 warp 以 256 个寄存器为粒度向上取整） |
| Shared Memory | 164 KB / SM | 每 block 申请的字节数（含静态 + 动态） |

**手算例题（高频，务必练到 30 秒内）**

> `__global__ void k(...)`，block = 256 线程，编译器报告每线程 40 个寄存器，静态 shared memory 8 KB。一个 SM 能常驻几个 block？occupancy 多少？

1. 线程：2048 / 256 = **8**
2. Warp：64 / (256/32=8) = **8**
3. Block 槽：**32**
4. 寄存器：每 warp 40×32 = 1280（是 256 的整数倍，不用上取整）；每 block 8 warp × 1280 = 10240；65536 / 10240 = 6.4 → **6**
5. Shared：164 KB / 8 KB = **20**

`min(8, 8, 32, 6, 20) = 6` 个 block → 6 × 8 = **48 warps** → occupancy = 48/64 = **75%**。

**追问：怎么把 occupancy 提到 100%？**
把每线程寄存器压到 32 个：32×32=1024/warp，每 block 8192，65536/8192 = 8 → 8 block × 8 warp = 64 warps = 100%。手段：`__launch_bounds__(256, 8)` 告诉编译器目标，或把中间变量压进 shared memory（要权衡），或减小 block size。

**这里有个陷阱，答出来是加分项**：**occupancy 不是越高越好**。GEMM 这类 ILP（指令级并行）充足的 kernel，在 25% occupancy 下就能跑到峰值算力的 90% 以上，因为每个线程有 8–16 个独立累加器，单个 warp 内部就能把延迟填满。官方文档明确说"高 occupancy 不一定带来高性能，但低 occupancy 一定削弱延迟隐藏能力"[R5]。所以正确说法是：**occupancy 是延迟隐藏的必要条件，不是性能指标**。

### 2.7 延迟隐藏：GPU 为什么需要这么多线程

| | CPU | GPU |
|---|---|---|
| 目标 | 降低**单线程延迟** | 提高**吞吐** |
| 手段 | 多级 cache、乱序执行、分支预测、投机 | 海量线程 + 快速上下文切换 |
| 晶体管花在哪 | 控制逻辑与 cache | **寄存器堆与执行单元** |

一次全局内存访问约 **400–800 周期**（量级，随架构变化 [R11]）。SM 的解决办法不是"等"，而是**把发这条指令的 warp 挂起，切到另一个就绪 warp**——上下文切换是零开销的，因为所有 warp 的上下文本来就住在寄存器堆里。所以需要 64 个 warp 来"喂饱"4 个 scheduler。

**为什么用寄存器堆而不是 cache 做延迟隐藏？** 面积账：cache 的 tag/比较逻辑很贵，而寄存器堆可以 100% 用于存上下文；而且 GPU 的数据是流式的，复用率低，cache 命中率上不去。这也是为什么 GPU 的 L1 只有 192 KB 而寄存器堆有 256 KB。

## 四、题库

### Q1. 一个 block 有 1000 个线程，硬件怎么分配 warp？

**30 秒答法**：`ceil(1000/32) = 32` 个 warp，最后一个 warp 只有 8 条 lane 有效，其余 24 条 mask 关闭。这 32 个 warp 会分摊到 SM 的 4 个 partition 上，每个 8 个。资源按 32 个 warp 分配（寄存器按 1024 线程算）。

**追问：为什么不是 31.25 个？** 因为 warp 是最小分配单位，不能拆。

**追问：这样有什么浪费？** 最后一个 warp 有 75% 的 lane 空转，理论算力损失约 2.3%（24/1024）。同时它占满 32 个 warp 槽的一半。

---

### Q2. `if (threadIdx.x < N)` 这种边界检查会有 warp divergence 吗？

**30 秒答法**：**绝大多数情况下没有**。因为 `threadIdx.x` 在 warp 内是连续的，条件在 warp 内部要么全真要么全假（warp-uniform），不产生分歧。只有当 N 不是 32 的倍数时，**唯一跨界的那一个 warp** 才会 divergence。

**追问：那为什么还要担心它？** 不用太担心，这就是为什么 kernel 末尾加边界检查的代价几乎可以忽略。真正贵的是数据相关分支。

**追问：如果条件是 `if (a[i] > 0)` 呢？** 这是数据相关分支，warp 内不可预测，最坏 2× 串行化。优化方向是让相邻线程处理相似数据（空间局部性），或用谓词化（`SEL` 指令）避免跳转。

---

### Q3. 一个 SM 上能同时跑多个 block 吗？什么时候不能？

**30 秒答法**：能，最多 32 个 block / 64 个 warp。一个 block 实际能拿到多少资源由四大约束决定。如果单个 block 用了 163 KB shared memory，那么这个 SM 就只能放 1 个 block，occupancy 会被压到很低（除非 block 本身有 1024 线程）。

**追问：如果 block 需要 40 KB shared memory 呢？** 164/40 = 4 个 block（向下取整），若要最大 occupancy，需要 block ≥ 512 线程才能凑到 4×16=64 warps。

---

### Q4. 为什么 grid 的 block 数要远大于 SM 数？

**30 秒答法**：三个原因。① **tail effect**：最后一批 block 会只剩少数 SM 在工作，GPU 利用率断崖式下跌，官方文档专门拿 12 个 block / 8 个 SM 举例（两波，第二波只有 50% 利用率）[R7]。② **负载不均衡**：block 做完的时间不一样，需要更多 block 来"填缝"。③ **隐藏调度延迟**：block 分配本身有开销。

**追问：那如果把 grid 设得超大呢？** 每个 block 的启动/收尾开销会被放大，寄存器/共享内存的分配也要重做。**更好的做法是 grid-stride loop**：grid 大小固定为 `SM数 × 每SM block数 × 若干倍`，每个线程用循环处理多个元素，一次 launch 做完，既省启动开销又保留 tail 平滑。

---

### Q5. 同一个 kernel 在 A100 和 RTX 4090 上跑，occupancy 会一样吗？

**30 秒答法**：会不同。4090 是 CC 8.9，每 SM 2048 线程 / 64 warp，但 shared memory 只有 100 KB/SM，L2 是 72 MB，SM 数是 128。同样的 8 KB shared memory 使 4090 只能放 12 个 block（100/8），如果 block 是 256 线程那就是 96 warps → 上限还是 64，所以这题要看具体参数。结论：**occupancy 是"设备相关"的，必须用 `cudaOccupancyMaxActiveBlocksPerMultiprocessor` 在目标设备上算，不能硬编码**。

（这题的价值在于展示你知道"不要拿消费卡的数字套数据中心卡"。）

---

### Q6. 代码走查：下面这段有什么问题？

```cpp
__global__ void add(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    c[i] = a[i] + b[i];
}
```

**30 秒答法**：三个问题。① **没有边界检查**，grid 上取整后会越界写；② 如果 `n` 远大于 grid 覆盖范围，**后面的元素根本没算**；③ 参数没有 `__restrict__`，编译器不敢假设指针不重叠，无法做 `LDG.CI` 只读缓存优化。

正确写法见 `code/01_vector_add.cu`（grid-stride + 边界检查 + `__restrict__`）。

1. **写出 3D 全局索引，并说明什么情况下 x 维会溢出。** （提示：x ≤ 2³¹−1 ≈ 21 亿，一般不会；但 `blockIdx.x * blockDim.x` 若用 `int` 计算，超过 2³¹ 会溢出成负数）
2. **给定 block=(16,16)、grid=(N/16, N/16)，求每 SM 能放几个 block**（自选寄存器 32、shared 0）。答：block 256 线程、8 warp；寄存器 8×1024=8192 → 8 个；线程 2048/256=8 → 8 个；答案 8 个 = 100% occupancy。
3. **一个 warp 里 32 个线程分别访问 `a[i]` 和 `a[2*i]`，哪个更快？为什么？** （这题其实是 W2 的合并访存，但 W1 就要能说出"warp 的访存会被合并成一个事务"）
