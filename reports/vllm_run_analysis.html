链路要点（均经源码核对）

  • 进程边界：主进程只跑 ①–③ 与 ⑩–⑪；真正的调度/执行在 EngineCore 子进程（④–⑨）。二者经 ZMQ / 共享内存通信，规避 GIL 瓶颈。
  • 异步调度：日志 Asynchronous scheduling is enabled → 走 step_with_batch_queue()（core.py:528），后台线程并行 schedule() + execute_model() + sample_tokens()。
  • Slot 映射：⑧ 的 _update_states() 内部调用 Triton kernel _compute_slot_mapping_kernel——这正是推理期被 JIT 监控告警的那个 KV cache 块管理 kernel。
  • Detokenizer 位置：文本生成（"Joel, my dad is..."）发生在 ⑩ 主进程的 OutputProcessor，而非 GPU Worker 内。

CUDA Graph 捕获尺寸分布

PIECEWISE 模式捕获全部 51 张图（最大 batch=512）；FULL 模式捕获 35 张（最大 batch=256）。捕获耗时约 2s，占 0.19 GiB。自 v0.21.0 起默认开启 CUDA graph 显存 profiling。

启动与推理时间线 TIMELINE

启动成本主要来自 torch.compile（13.54s） 与 模型加载（12.57s）；二者均已命中缓存（torch_compile_cache），二次冷启将大幅加速。推理本身对本例 4 条短 prompt 可忽略不计。

日志关键发现 FINDINGS

⚠ 版本不一致：运行时 v0.22.0 vs 源码树 v0.23.1rc0

日志引擎初始化打印 (v0.22.0)，但本地 git checkout 为 v0.23.1rc0+1062，且日志含 VLLM_PRECOMPILED_WHEEL_* 变量——说明运行加载的是已安装的 0.22.0 wheel。若需验证 0.23.1 新特性，须 pip install -e . 或设 PYTHONPATH。

① 5 个未知环境变量告警（无害）

VLLM_SRC / VLLM_PRECOMPILED_WHEEL_VARIANT / VLLM_ENV_ROOT / VLLM_SOURCE_ROOT / VLLM_PRECOMPILED_WHEEL_LOCATION 未登记到 envs.py 注册表，触发 validate_environ() 告警。属内部构建/CI 变量，建议 unset 以消除刷屏。

② 推理期 Triton JIT 尖峰（生产需消除）

_compute_slot_mapping_kernel（KV cache slot 映射）未被 warmup 覆盖，首个推理步才首次编译，被 jit_monitor.py 捕获为延迟尖峰。扩展 warmup 或预编译该 kernel 即可消除。

③ 输出 incoherent 是正常现象（非 bug）

"Joel, my dad is my friend..." 等发散续写源于 OPT-125m 是 125M base 预训练模型（非指令微调）。流水线完全正确；换 1B+ 或 instruct 模型即可见连贯输出。
